# 05 — 开发路线图

## 总体原则

```
目标：3 个阶段交付可用的 SaaS 多租户平台
策略：核心先行，每阶段结束都可独立运行
```

---

## 阶段一：基础骨架 + 认证与租户管理（第 1-4 周）

**目标：** 完成项目骨架搭建、多租户基础设施、认证体系。阶段结束后，可以注册租户、登录、管理用户/角色/部门。

### 里程碑 1.1 — 项目骨架（第 1 周）

| 任务 | 产出 |
|------|------|
| 创建 Maven 多模块项目结构 | 父 pom + 6 个服务 + 7 个 common 模块 |
| 配置 Spring Cloud + Nacos | 服务注册/发现/配置中心 |
| Docker Compose 编排 | MySQL + Redis + Kafka + Nacos + MinIO + Zipkin 一键启动 |
| 数据库初始化脚本 | 5 个库的建表 SQL + 初始数据 |
| Gateway 基础路由 | 路由转发到各服务 |
| common-core | R<T> 响应体、全局异常处理、工具类 |
| common-data | MyBatis-Plus 配置、审计字段自动填充 |
| common-redis | RedisTemplate 配置 |

```
验收标准:
  ✅ docker-compose up 一键启动所有中间件
  ✅ 各服务启动成功，注册到 Nacos
  ✅ Gateway 能路由到各服务的 /actuator/health
```

### 里程碑 1.2 — 多租户基础设施（第 2 周）

| 任务 | 产出 |
|------|------|
| TenantContext (TransmittableThreadLocal) | 租户上下文传播 |
| TenantSqlInterceptor (MyBatis) | SQL 自动注入 tenant_id |
| TenantContextFilter | 从 Gateway Header 构建租户上下文 |
| TenantFeignInterceptor | Feign 调用传播 tenant_id |
| common-security 模块 | JWT 工具、签名验证、@RequirePermission 注解 |
| Gateway JWT 解析 + 签名注入 | 全局认证过滤器链 |
| Gateway 租户状态校验 | Redis 缓存租户状态，冻结则 403 |

```
验收标准:
  ✅ 请求链路: Gateway → 下游服务，租户上下文完整传播
  ✅ SQL 自动带 tenant_id，白名单表跳过
  ✅ Feign 服务间调用租户上下文不丢失
  ✅ @Async 场景下 TenantContext 正确传播
```

### 里程碑 1.3 — 平台管理 + 认证（第 3 周）

| 任务 | 产出 |
|------|------|

| platform-service: 套餐管理 | CRUD + 套餐菜单配置 |
| platform-service: 配额校验接口 | 内部 Feign 接口 |
| platform-service: 平台用户管理 | 平台管理员 CRUD + 登录 |
| rbac-service: 租户注册流程 | 注册 → 自动创建租户/用户/角色/部门 |
| rbac-service: 登录/登出/Token 刷新 | 双 Token + Redis 黑名单 |

```
验收标准:
  ✅ 平台管理员可登录平台后台
  ✅ 可创建套餐，设置配额
  ✅ 可通过注册接口创建租户
  ✅ 租户用户可登录，获取 JWT
  ✅ Token 刷新 + 黑名单踢出机制正常
```

### 里程碑 1.4 — RBAC 权限体系（第 4 周）

| 任务 | 产出 |
|------|------|
| rbac-service: 用户管理 | CRUD + 启用禁用 + 密码重置 + 邀请制 |
| rbac-service: 角色管理 | CRUD + 菜单分配（套餐约束） + 数据范围 |
| rbac-service: 部门管理 | CRUD + ancestors 维护 + 部门树 |
| rbac-service: 菜单管理 | 平台级菜单 CRUD（仅平台超管） |


## 阶段二：流程引擎 + 通知中心（第 5-8 周）

**目标：** 完成流程设计、审批流转、通知推送。阶段结束后，租户可以设计流程、发起审批、接收通知。

### 里程碑 2.1 — 流程设计与部署（第 5-6 周）

| 任务 | 产出 |
|------|------|
| Flowable 引擎集成 | Process Engine 配置、租户隔离 |
| 流程定义扩展表 CRUD | 流程定义管理 + 表单配置 |
| BPMN 部署接口 | XML 解析 → Flowable 部署 → 扩展表关联 |
| 节点审批人配置 | 指定用户/角色/部门负责人/发起人自选 |
| 版本管理 | 新版部署、旧版实例继续运行 |
| 挂起/激活 | 挂起后不可发起新实例 |
| 平台模板 | 预置请假/报销/合同模板 + 租户导入 |
| 配额校验 | 流程定义数量受套餐限制 |

```
验收标准:
  ✅ 可通过 API 上传 BPMN XML 并部署
  ✅ 节点审批人配置可设置多种规则
  ✅ 预置模板可一键导入到租户
  ✅ 流程定义数超限时提示升级
```

### 里程碑 2.2 — 流程审批流转（第 7 周）

| 任务 | 产出 |
|------|------|
| 发起流程 | 创建实例 + 表单数据 + 首个任务推送 |

| 抄送 | 节点完成后抄送指定人 |
| 流程图高亮 | 返回当前节点高亮信息 |
| 审批时间线 | 完整的审批历史 |

```
验收标准:
  ✅ 完整流程: 发起 → 审批 → 完成/驳回
  ✅ 转办、委派、加签正常
  ✅ 撤回机制正常
  ✅ 流程图能正确高亮当前节点
```

| 任务 | 产出 |

## 技术风险与应对

| 风险 | 影响 | 应对 |
|------|------|------|
| Flowable 多租户隔离 | Flowable 内置表不带 tenant_id | 使用 Flowable 的 TenantId 机制 + 扩展表做业务隔离 |
| 微信接口限频 | API 调用频率受限 | 批量操作分页+延时、AccessToken 集中管理避免重复获取 |
| MyBatis 拦截器覆盖面 | 手写 SQL 可能绕过拦截器 | 编码规范 + Code Review 必查 tenant_id、测试用例验证隔离 |
| JWT 内嵌权限体积 | 权限多时 Token 过大 | 压缩权限字符串、超过阈值时回退 Redis 方案 |
| 跨服务数据一致性 | Feign 调用失败导致不一致 | 关键操作用 Kafka 事件保证最终一致、降级策略兜底 |
